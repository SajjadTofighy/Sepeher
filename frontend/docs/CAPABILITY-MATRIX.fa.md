# تطبیق قابلیت‌ها با طرح

بازبینی ۲۰۲۶-۱۰-۰۸: [گزارش کامل تطبیق و نواقص باقی‌مانده](DESIGN-REVIEW.fa.md).

تعریف «پیاده‌سازی نمایشی»: فرم، مسیر کاربر و API قابل اجرا وجود دارد؛ ورودی‌ها و رفتار دستگاه/تحلیل ساختگی‌اند. این جدول ادعای آمادگی عملیاتی نیست.

| بخش طرح | محل در محصول | وضعیت این تحویل |
|---|---|---|
| موقعیت نیرو، خودرو و رخداد | مرکز فرماندهی | نقشه روی کل محدوده عملیاتی باز می‌شود؛ حرکت زنده و قطعی (deterministic) گشت‌ها با سرعت؛ موقعیت گزارش‌شده واقعی همیشه بر شبیه‌سازی مقدم است |
| مشخصات، باتری، سیگنال، مأموریت | ناوگان / پنل تجهیز | نمایش و ویرایش مشخصات سیم‌کارت |
| محدوده‌های حفاظت | محدوده‌ها و لایه‌ها | ایجاد/ویرایش چندضلعی مختصاتی؛ خروجی GeoJSON |

| گشت غیرقابل پیش‌بینی مبتنی بر ریسک (§۱۰، قابلیت ۲، پایه) | app/intel/risk، نقشه و عملیات گشت | جمع وزن‌دار چهار عامل ثابت با ریز محاسبه و یافته منبع؛ لایه ریسک قطعه‌ها؛ دسترسی ناموجود خنثی با برچسب. نیمه‌عمر رخدادها کاهش وزن زمانی ثابت است؛ یادگیری از سوابق گشت و تنظیم خودکار وزن‌ها فاز ۳ و خارج از این تحویل است |
| گزارش خودکار شیفت (§۱۰، قابلیت ۸) | داشبورد مدیریتی / گزارش شیفت و reports/shift | هفت بخش از رکوردهای موجود با قالب فارسی و شناسه منابع؛ آخرین شیفت کامل‌شده به وقت تهران یا بازه دلخواه؛ پوشش و قطعی در پایان بازه از وقایع ثبت‌شده، زمان چرخه بدون خط مبنای نمونه، بازدید/ازدست‌رفتن/مهلت باز ایستگاه؛ پرچم گزارش جزئی و data_since پس از شروع/بازنشانی؛ چاپ و JSON، بدون تشخیص جدید یا فرمان، و audit یک‌بار در هر مرز شیفت بدون ذخیره نسخه گزارش |
| افت فشار خط لوله (§۱۰، قابلیت ۴، زیرساخت فاز ۳) | intel/ingest/pipeline-pressure | پیش‌فرض غیرفعال و نیازمند مجوز بهره‌برداری و اتصال یک‌طرفه؛ فقط رخداد ورودی صریح، نگاشت فاصله طولی/شناسه قطعه، یافته pressure_drop و پرونده با مسیریابی مشترک، پیشنهاد نزدیک‌ترین گشت آزاد و آخرین بازدید پوشش. حالت پیش‌فرض سایه؛ اتصال واقعی و هویت منبع احراز نشده؛ هیچ نوشتنی به کنترل فرایند وجود ندارد |
| پلاک‌خوان (§۱۰، قابلیت ۵، زیرساخت فاز ۳) | intel/ingest/plate-read و engine | پیش‌فرض غیرفعال؛ خودروی سنگین خارج از فهرست مجاز در شب و تکرار همان پلاک در حداقل دو دوربین حساس در پنجره قابل تنظیم، با unknown_vehicle/camera_event موجود؛ یافته مستند و مسیریابی سیاست. فقط خوانش صریح، بدون تولید داده نمونه، تشخیص تصویر یا اعزام خودکار؛ adapter قدیمی دوربین همان مسیر ورودی را استفاده می‌کند |
| ناهنجاری خودروهای سازمانی (§۱۰، قابلیت ۶) | پیش‌نیاز سازمانی | تشخیص یا endpoint ندارد؛ نیازمند سیاست حریم خصوصی مصوب، هویت واقعی و RBAC (§۱۴) و ثبت audit دسترسی مشاهده‌کننده است |
| تجمیع نقاط | MapLibre | clustering در زوم پایین؛ fallback بدون clustering |
| بازپخش | تاریخچه و پنل تجهیز | مسیر زمان‌محور، کنترل پخش/توقف و تاریخچه پایدار SQLite؛ بازسازی جامع وضعیت تاریخی منطقه ناقص است |

| ۱۲ سناریوی سیاست | فرم سیاست / موتور سیاست | نه شرط ورود، تردد در بازه ممنوع، توقف، قطع ارتباط، جهش GPS، SOS، نرسیدن به ایستگاه زمان‌دار و دو شرط ورودی واقعی پلاک اجرایی‌اند؛ آزمون از GPS، ایستگاه زمان‌دار یا خوانش واقعی مطابق شرط استفاده می‌کند. سه شرط دیگر فقط پیش‌نویس‌اند و آزمون/فعال‌سازی آن‌ها رد می‌شود |

| کنترل حجم هشدار | مدیریت / سیاست‌ها | سیاست سایه فقط ثبت می‌کند؛ هشدار تکراری در پنجره dedupe در پرونده باز ادغام می‌شود؛ سکوت مانور مسیریابی را متوقف و هشدار را ثبت می‌کند؛ گزارش «هشدارهای موتور سیاست». سایه سراسری و آستانه پوشش عادی/ضعیف هر محدوده اعمال می‌شود؛ گزارش ماهانه و بازبینی نرخ کاذب هنوز پیاده نشده |
| پرونده و اعزام | حوادث / حالت فرماندهی حادثه | ثبت دستی حادثه فرایندی و چرخه شش‌مرحله‌ای؛ تمرکز نقشه با حلقه حادثه؛ گشت اعزامی با زمان فشرده نمایشی روی نقشه حرکت می‌کند و رسیدن از موقعیت ثبت می‌شود |
| پیشنهاد نزدیک‌ترین گشت | پنل حادثه / نقشه | فاصله مستقیم و زمان رسیدن **تخمینی** (×۱٫۳، ۴۵ km/h) با برچسب صریح؛ خط‌چین گشت‌های نامزد روی نقشه؛ فقط گشت‌های برخط و فاقد پرونده باز دیگر قابل اعزام‌اند |
| گزارش خودکار | پنل حادثه | گزارش قابل چاپ/PDF مرورگر با خط زمانی، نیروها، سیاست منبع، زمان‌های واکنش و محدوده خطر و فهرست داخل/نزدیک‌شونده؛ خروجی JSON |
| گشت و ایستگاه | عملیات گشت / app/intel/patrol | پیشنهاد برنامه پایه با یک هدف دیرکرد الزامی، نمونه‌گیری وزن‌دار بدون تکرار، زمان‌های تصادفی با تفاوت از سه برنامه تأییدشده اخیر؛ پیش‌نمایش شماتیک و ریز عوامل ریسک؛ تأیید/کنارگذاشتن audited و ایجاد مأموریت بدون اعزام. بازدید هدف توسط گشت مأموریت در پنجره مهلت از پوشش ثبت و نرسیدن در موتور سیاست بررسی می‌شود؛ ایستگاه‌های قدیمی دستی سازگارند |

| تصویر زنده دوربین | کارت دوربین | محل و وضعیت طراحی شده؛ ویدئو متصل نیست |

| نقش‌ها و حریم خصوصی | مدیریت سامانه | ماتریس نمونه نقش‌ها و فرم retention؛ enforcement واقعی ندارد |

| نمایش پنج‌دقیقه‌ای (پیوست طرح) | دکمه «نمایش ۵ دقیقه‌ای» | هفت مرحله راهنما روی APIهای واقعی: ورود بدون مجوز ← تشخیص موتور ← فرماندهی ← اعزام و حرکت ← نقشه راه فاز ۳ ← خاتمه با زمان‌ها ← بازپخش |
| گسترش به شرکت‌های دیگر | معماری / DTO / feature boundary | مسیر توسعه مستند؛ tenancy عملیاتی ندارد |

موتور سیاست برای نه شرط و دریافت موقعیت HTTP و ذخیره پایدار مسیر موجود است. بازسازی جامع تاریخچه، ویدئو، هویت سازمانی، درگاه پروتکل دستگاه/پیامک، ذخیره پایدار عملیات، سه شرط دیگر، تشخیص ناهنجاری خودروی سازمانی و LLM همچنان ناقص یا نمایشی‌اند. هیچ شبیه‌سازی با اتصال واقعی معرفی نشده است.
